# CloudFront CDN Setup for Dataset Distribution

## Overview

The Weather Platform uses Amazon CloudFront to distribute processed weather datasets globally with low latency and high availability. The CDN serves CSV files generated by the ETL pipeline to end users and applications.

## Architecture Components

### CloudFront Distribution

- **Distribution ID**: Available in amplify_outputs.json
- **Domain Name**: `*.cloudfront.net`
- **Price Class**: PriceClass_200 (US, Canada, Europe, Asia, Middle East, Africa)
- **HTTP Version**: HTTP/2 and HTTP/3 support

### Origin Configuration

- **Origin Type**: S3 bucket
- **Origin ID**: weather-dataset-s3-origin
- **Source**: Amplify storage bucket
- **Access Control**: Origin Access Control (OAC)

## CloudFront Configuration

### Default Cache Behavior

- **Viewer Protocol**: HTTPS only
- **Allowed Methods**: GET, HEAD, OPTIONS
- **Cached Methods**: GET, HEAD, OPTIONS
- **Compression**: Enabled (Gzip and Brotli)

### Cache Policy

- **Name**: `{id}-weather-dataset-cache`
- **Default TTL**: 86400 seconds (1 day)
- **Maximum TTL**: 2592000 seconds (30 days)
- **Minimum TTL**: 3600 seconds (1 hour)

### Headers Configuration

Whitelisted headers for CORS support:

- `Access-Control-Request-Headers`
- `Access-Control-Request-Method`
- `Origin`

### Query String Handling

- **Behavior**: Forward all query strings
- **Purpose**: Support dynamic district-based filtering

## Origin Access Control (OAC)

### Configuration

- **Name**: `{id}-weather-dataset-oac`
- **Origin Type**: S3
- **Signing Behavior**: Always
- **Signing Protocol**: SigV4
- **Description**: Origin Access Control for Weather Dataset S3 Bucket

### Security Benefits

- Prevents direct S3 access
- Ensures traffic goes through CloudFront
- Maintains S3 bucket security

## S3 Bucket Policy

The bucket policy controls access to the dataset files:

### CloudFront Access

```json
{
  "Sid": "AllowCloudFrontGetObject",
  "Effect": "Allow",
  "Principal": { "Service": "cloudfront.amazonaws.com" },
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::bucket-name/*",
  "Condition": {
    "StringEquals": {
      "AWS:SourceArn": "arn:aws:cloudfront::account:distribution/distribution-id"
    }
  }
}
```

### Account Access

Allows account principals to access specific prefixes:

- `dataset/*`: Processed weather data
- `glue-scripts/*`: ETL scripts

### External Access Denial

Denies access to external principals except through CloudFront:

```json
{
  "Sid": "DenyExternalGetObjectExceptCloudFront",
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::bucket-name/*",
  "Condition": {
    "StringNotEquals": {
      "AWS:SourceArn": "arn:aws:cloudfront::account:distribution/distribution-id"
    },
    "StringNotLike": {
      "aws:PrincipalArn": "arn:aws:iam::account:*"
    }
  }
}
```

### S3 Bucket Organization

```
s3://bucket-name/
├── dataset/
│   ├── district1/
│   │   ├── all_data_20240101_120000.csv
│   │   └── all_data_20240102_120000.csv
│   ├── district2/
│   │   ├── all_data_20240101_120000.csv
│   │   └── all_data_20240102_120000.csv
│   └── ...
├── glue-scripts/
│   └── weather-transform.py
└── temp/
    └── glue-temp-files/
```

### Dataset Files

- **Format**: CSV with headers
- **Naming**: `all_data_{YYYYMMDD_HHMMSS}.csv`
- **Content**: Complete historical data per district
- **Partitioning**: By district/location

## CDN URL Patterns

### Direct File Access

```
https://{distribution-domain}/dataset/{district}/all_data_{timestamp}.csv
```

### Examples

```
https://d1wbddrjyd2c3o.cloudfront.net/dataset/hanoi/all_data_20240101_120000.csv
https://d1wbddrjyd2c3o.cloudfront.net/dataset/hcmc/all_data_20240101_120000.csv
```

## Purpose and Benefits

### Performance Benefits

1. **Global Edge Locations**: Reduced latency worldwide
2. **Caching**: Frequently accessed datasets served from edge
3. **Compression**: Automatic Gzip/Brotli compression
4. **HTTP/2**: Improved performance for multiple requests

### Reliability Benefits

1. **High Availability**: Multiple edge locations
2. **DDoS Protection**: Built-in AWS Shield Standard
3. **Automatic Failover**: Between edge locations
4. **Monitoring**: CloudWatch metrics and logging

### Security Benefits

1. **HTTPS Enforcement**: All traffic encrypted
2. **Origin Access Control**: Secure S3 access
3. **Access Logging**: Request tracking
4. **Custom Headers**: CORS support for web applications

### Cost Benefits

1. **Reduced S3 Costs**: Less direct S3 requests
2. **Bandwidth Optimization**: Compression and caching
3. **Regional Pricing**: Price class optimization

## Integration with Application

### Frontend Access

The React application accesses datasets through:

```typescript
// From amplify_outputs.json
const cdnDomain = amplifyOutputs.custom.weatherCdnDomainName;

// Construct dataset URL
const datasetUrl = `https://${cdnDomain}/dataset/${district}/all_data_${timestamp}.csv`;
```

### API Integration

The getDataset Lambda function can:

1. List available datasets per district
2. Generate signed CloudFront URLs
3. Provide metadata about dataset files

## Monitoring and Analytics

### CloudWatch Metrics

- **Request Count**: Number of requests served
- **Bytes Downloaded**: Data transfer volume
- **Cache Hit Ratio**: Caching efficiency
- **4xx/5xx Errors**: Error rates
- **Origin Latency**: S3 response times

### Access Logs

Optional CloudFront access logs provide:

- Request details and patterns
- Geographic distribution of users
- Popular datasets and districts
- Error analysis

## Configuration Management

### CDK Implementation

The CloudFront distribution is defined in:

- **File**: `amplify/custom/CloudFront/resource.ts`
- **Class**: `CustomCloudFront`
- **Properties**: Configurable bucket name and domain

### Outputs

The following values are exported to amplify_outputs.json:

- `weatherCdnDomainName`: CloudFront distribution domain
- `weatherCdnDistributionId`: Distribution ID for management

## Deployment Considerations

### Initial Setup

1. S3 bucket must exist before CloudFront creation
2. OAC must be created before distribution
3. Bucket policy applied after distribution creation

### Updates and Changes

1. Cache invalidation may be needed for immediate updates
2. Distribution updates take 15-30 minutes to deploy
3. DNS propagation may take additional time

### Security Considerations

1. Regular review of bucket policies
2. Monitor access patterns for unusual activity
3. Consider AWS WAF for additional protection
4. Implement request rate limiting if needed

## Troubleshooting

### Common Issues

1. **403 Forbidden**: Check OAC and bucket policy configuration
2. **Cache Issues**: Use invalidation or cache headers
3. **CORS Errors**: Verify headers configuration
4. **Slow Performance**: Check price class and edge locations

### Debug Steps

1. Test direct S3 access (should be denied)
2. Verify CloudFront can access S3
3. Check distribution status and configuration
4. Review CloudWatch metrics and logs

# AWS Cognito Authentication Setup

This guide covers setting up AWS Cognito authentication for your Amplify Gen 2 Next.js application.

## Prerequisites

- Amplify backend already initialized (see [Manual Setup Guide](../manual_setup.md))
- AWS Cognito User Pool and Identity Pool created during sandbox deployment

## Next.js Application Setup

### Import Amplify Outputs

In your Next.js app components, import the generated configuration:

```typescript
import outputs from "../amplify_outputs.json";
```

This file is automatically generated when you run `npx ampx sandbox` and contains all the necessary configuration for your Cognito setup.

## Cognito User Management

### Launching Amazon Cognito

After running the setup steps in the manual setup guide, Amazon Cognito will be deployed in your sandbox environment with:

- User Pool for authentication
- Identity Pool for authorization
- Configured authentication flows

### Setting Up Users

1. **Navigate to AWS Cognito Console**

   - Go to the AWS Console
   - Navigate to Amazon Cognito
   - You will see a User Pool and Identity Pool already created

2. **Create a New User**
   - From User pools, navigate to the **Users** section
   - Click **Create User**
   - Provide the user's email address
   - Set a temporary password
   - If creating for other people, select **Send an email invitation** (optional)

### Setting Up Groups (Optional)

1. **Create User Group**

   - Go to **Groups** section in your User Pool
   - Click **Create group**
   - Group name: `platform-admin`

2. **Configure IAM Role**

   - Trust entity type: **Web identity**
   - Identity Provider: **Amazon Cognito**
   - Identity Pool ID: (paste from Amazon Cognito Identity Pool)
   - Click **Save changes**

3. **Add User to Group**
   - Select the created user
   - Add them to the `platform-admin` group

## User Account States

According to the Amazon Cognito developer guide, user accounts have 4 confirmation states:

- **Registered (Unconfirmed)**: User registered but not confirmed
- **Confirmed**: User is confirmed and can sign in
- **Password Reset Required**: User must reset password
- **Force Change Password**: User must change password before first sign-in
- **Disabled**: User account is disabled

### Important: Administrator-Created Users

When user accounts are created by an administrator or developer, the status will be **Force Change Password**. Users cannot log in with this account until they change their password.

**Common Error**: If a user tries to log in without changing their password first, you'll get:

```
"User needs to be authenticated to call this API" (error 400 - Bad Request)
```

### Password Change Process

Users with **Force Change Password** status must:

1. Attempt to sign in with temporary credentials
2. Be prompted to change password
3. Set a new password
4. Account status changes to **Confirmed**
5. User can now sign in normally

## Implementation in Next.js

### Basic Authentication Setup

```typescript
import { Amplify } from "aws-amplify";
import outputs from "../amplify_outputs.json";

Amplify.configure(outputs);
```

### Sign-in Form Implementation

```typescript
import { signIn, signOut, getCurrentUser } from "aws-amplify/auth";

// Sign in function
async function handleSignIn(username: string, password: string) {
  try {
    const { isSignedIn, nextStep } = await signIn({
      username,
      password,
    });

    if (nextStep.signInStep === "CONFIRM_SIGN_IN_WITH_NEW_PASSWORD_REQUIRED") {
      // Handle password change requirement
      console.log("Password change required");
    }

    return { isSignedIn, nextStep };
  } catch (error) {
    console.error("Error signing in:", error);
    throw error;
  }
}

// Get current user
async function checkAuthStatus() {
  try {
    const user = await getCurrentUser();
    return user;
  } catch (error) {
    console.log("Not authenticated");
    return null;
  }
}
```

### Handling Password Change

```typescript
import { confirmSignIn } from "aws-amplify/auth";

async function handleNewPasswordRequired(newPassword: string) {
  try {
    const { isSignedIn } = await confirmSignIn({
      challengeResponse: newPassword,
    });

    if (isSignedIn) {
      console.log("Password successfully changed, user signed in");
    }

    return isSignedIn;
  } catch (error) {
    console.error("Error changing password:", error);
    throw error;
  }
}
```

## Testing Authentication Flow

1. **Create a test user** in Cognito Console
2. **Attempt sign-in** with temporary credentials
3. **Handle password change** requirement
4. **Verify successful authentication**

## Troubleshooting

### Common Issues

1. **"User needs to be authenticated to call this API"**

   - Solution: User needs to change password first

2. **Authentication fails silently**

   - Check if amplify_outputs.json is properly imported
   - Verify Cognito configuration in AWS Console

3. **Password requirements not met**
   - Check User Pool password policy
   - Ensure new password meets complexity requirements
